THREADLINE / DEVELOPER NOTES

Developer API

Version 1. Read-only access to your own profile and photographs. No messages, passwords, recovery codes, follower identities, or other accounts' data.

Create a key

Sign in to Threadline, open your Profile, then Developer API. Name the key and copy it when it appears. The full key appears only once and is not saved in your browser. Keep it on your server, never in a public website or source repository. Up to five active keys per account.

Authentication

Use an API key in the Authorization header. A regular Threadline session token does not work with v1, and API keys do not work with app/session endpoints.

Authorization: Bearer YOUR_API_KEY

Use this site's HTTPS origin as the base URL. Never send your key to another host. Example:

curl -H 'Authorization: Bearer YOUR_API_KEY' \
  'https://YOUR_THREADLINE_HOST/api/v1/me'

GET /api/v1/me

Returns your profile: id, handle, name, bio, avatar path (or null), follower count, following count, post count, and followedByMe (false for self). Counts only, no relationship identities.

GET /api/v1/posts

Returns your own photographs, newest first. Query: limit (1 to 50, default 20), before (positive post id). Use the returned next cursor to fetch the next page. Null means the end. Image paths are relative to this site's origin. Image URLs are already public to anyone who has them.

{
  "posts": [{
    "id": 42, "image": "/uploads/IMAGE_KEY.jpg",
    "caption": "Your caption", "created": 1791240000000,
    "width": 1200, "height": 1600
  }],
  "next": null
}

This response is an illustrative example, not live account data. Width and height may be null for older photographs. Times are Unix milliseconds. Invalid limits fall back to 20; limits over 50 are capped. An invalid before value starts from the newest page.

Rate limits

Each key allows 60 authenticated requests per fixed UTC minute, enforced atomically in the shared database across servers. Responses include X-RateLimit-Limit, X-RateLimit-Remaining and X-RateLimit-Reset (Unix seconds). A 429 response includes Retry-After with the number of seconds until the next minute. Wait, then retry. Do not rotate keys or servers to evade limits.

Errors

{ "error": "A valid API key is required" }
  • 401: missing, invalid, revoked or recovery-invalidated key.
  • 404: unknown endpoint. Only GET /api/v1/me and GET /api/v1/posts are supported.
  • 429: current key allowance reached.
  • 500: server problem. Back off before retrying.

Responses are JSON and use Cache-Control: no-store. There is no mutation API in v1. Keys do not grant access to the app's other endpoints.

Revoke and rotate

Revoke a key from your Profile's Developer API screen. Revocation prevents future authorized requests; a request already authorized may finish. Create a replacement key and update your server. Account recovery invalidates and revokes existing developer keys. Logging out does not revoke them.

Limits and availability

This is a small, free-hosted service. Sleeping hosts, restarts and provider quotas can interrupt access. No uptime guarantee. The API does not expose YouTube discovery or playback to developers. Never cache or redistribute private account data without its owner's permission.
