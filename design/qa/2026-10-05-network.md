# Network and startup checkpoint

October 5, 2026, 08:50-08:52 PDT. Local disposable server and accounts only.

- Chromium simulated 150 ms network latency, 200 KiB/s download, 100 KiB/s upload and 4x CPU slowdown. Landing LCP was 2216 ms, CLS 0.000035. This is a warm local-server test, not a production or cold free-instance benchmark. Main JS transferred about 62 KiB, CSS 16 KiB, sans font 89 KiB, serif font 28 KiB and sample photograph 167 KiB. No page errors.
- A signed-in offline reload retains the token, shows the startup connection error and retry rather than false empty content or an invitation to create a duplicate account. Online retry restores the same account. Passed.
- A twelve-photo feed fetches five images at startup rather than all twelve at once. First image is eager/high priority; later images are lazy. Scrolling to the last photograph loads it successfully without horizontal overflow. Passed.
- Inspected captured pixels of the slow-network landing, offline retry, recovered profile and bottom feed photograph. Text, retry actions, navigation and complete image composition are readable and correctly placed.

New specs are included in the default runner: slow-startup, offline-session and lazy-feed. No runtime change is justified by this checkpoint. Production still c52828e; the test-only changes are batched locally.

Open limits: physical iPhone installation is not verified; the local startup timing excludes Render's potential cold-start delay. Browser-owned HTTP caches may keep publicly served image bytes; app-managed CacheStorage excludes uploads and API responses.
